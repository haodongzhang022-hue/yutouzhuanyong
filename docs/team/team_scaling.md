# V2 团队规模设计与分工（供经理安排开发）

> 基于 8 个功能模块（见 v2_02 功能模块地图），按"先粗纲→功能模块→细纲"拆成**可独立指派、可独立验收**的工作包。
> 本文件给出：建议团队规模、角色分工、每模块 RACI、依赖与排期建议、接单人参照。

---

## 1. 建议团队规模

按当前项目规模（题库系统 + 单库 + 中小迭代节奏），**推荐 3~5 人并行**即可覆盖一个里程碑。

| 规模 | 适用 | 结构 |
|------|------|------|
| 最小可跑（3人） | MVP/演示 | 1 全栈主程 + 1 后端 + 1 测试/文档 |
| 推荐（4~5人） | 正式迭代并行 | 1 架构把关(总师) + 2 后端/框架 + 1 前端(可选) + 1 测试&内容 |
| 不建议超过 6 | 避免上下文耦合 | 模块间共享 DB/Schema，人过多同步成本高 |

> 依据：M2/M3 共享组织层代码，M1/M4/M5 依赖同一 DB Schema；并行单元建议 ≤ 5，否则 schema 冲突与联调成本陡增。

## 2. 角色与职责

| 角色 | 责任 | 建议人 |
|------|------|--------|
| **架构总师** | 把关模块边界/决策，不改主线、审细纲 | 总师岗位 |
| **架构·总师助理** | 承接框架修正专项落地、产出本蓝本 | 本人(本角色) |
| 后端·数据(M1/M2) | 采集加固、schema、规范化索引、迁移 | 开发A |
| 后端·应用(M4/M5) | 练习闭环、API 契约、错误统一 | 开发B |
| 框架/基建(M6/M7) | 配置中心、观测、生命周期、DI 工厂 | 开发C |
| 内容·专项卷(M3/M8) | 渲染模板、增量重建、题源/知识点目录、validate | 开发D(或A兼) |
| 测试 | 全链路/组织层/边界用例 | 开发E(测试) |
| 前端(可选) | 练习/错题/目录页 | 开发F |

## 4. 里程碑排期与人力分配（建议 4 人，5~8 周）

| 里程碑 | 交付 | 主导 | 协助 | 工期 |
|--------|------|------|------|------|
| **M0 基建落地** | M7 框架 + M6 观测 + 工厂化 | C(框架) | B | 1~2 周 |
| **M1 采集加固** | M1 重试/幂等/健康 + M8 源管理 | A | C、D | 1 周 |
| **M2 组织闭环** | M2 索引回填 + M3 增量重建/版本化 + API /papers | D、B | A | 2 周 |
| **M3 练习闭环** | M4 练习/错题/计划 + M5 相应端点 | B | A | 1~2 周 |
| **M4 打磨上线** | 全量测试/部署/validate | 全员 | 测试 | 1 周 |

> 并行约束：M2 依赖 M0+M1；M3/M4 可并行于 M2 之后。总师在每个里程碑末做 CP 把关（见下）。

---

## 5. 把关确认点（CP，供总师/经理放行）

- **CP-A（M0 后）**：基建可跑，配置/日志/健康/工厂化验收通过，再进入业务模块。
- **CP-B（M2 后）**：采集→组织→卷增量重建链路闭环，产物可寻址。
- **CP-C（M3 后）**：练习闭环全链路留痕，错题/统计正确。
- **CP-D（M4 后）**：全量回归通过，可上线。

每 CP 由架构总师批准；被打回则按"回转"规则返工，最多 3 次。
