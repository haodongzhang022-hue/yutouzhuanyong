# V2 框架蓝本 · 02 · 功能模块地图（模块职责 + 接口契约）

> 承接 `v2_00_粗纲`，把平台拆成 **8 个功能模块**。
> 每个模块给出：目标 / 承载目录 / 职责 / 对外契约(输入输出) / 依赖 / 验收要点。
> 供"经理按模块安排开发 + 架构总师把关"，并作为细纲各章的骨架。

---

## M1 · 采集存储层（采集器 + 去重入库 + Schema 演进）

- **承载**：`src/collectors/`、`src/models/`、`data/builtin/`
- **职责**
  1. 多源采集（builtin / json_api / web），统一规范化字段。
  2. 去重幂等入库（exam_type + source + external_id 唯一）。
  3. Schema 版本化管理与迁移（`schema_version`）。
  4. 源健康上报 + 单源失败隔离（不影响整批）。
- **输入**：源配置（`config/settings.yaml` collectors 段）
- **输出**：`questions` 表写入、`fetch_logs`、可选的"入库即回调组织"事件
- **契约**：对外暴露 `Collector.fetch(exam, count)`；入库后广播 `question.created`
- **依赖**：M7(配置/日志)、M6(指标)
- **验收**：源故障不崩溃；重复源零重复入库；schema 可平滑升级

---

## M2 · 组织索引层（知识点目录 + 规范化 + 双向索引）

- **承载**：`src/organization/`（kp_catalog/question_normalizer/topic_index）
- **职责**
  1. 知识点目录加载与 topic→kp 归并（承接 V1）。
  2. 单题/批量规范化（qid/type/kp_code/difficulty 统一编码）。
  3. 三维双向索引（by_kp / by_type / by_difficulty），支持任意组合检索。
- **输入**：规范化题流（可来自 DB 或 builtin）
- **输出**：规范化对象 + 索引；供 M3 渲染、M5 API、M4 练习组合检索
- **契约**：`normalize_batch()` / `TopicIndex.query(kp,type,diff)`
- **依赖**：M1 数据、M7 路径
- **验收**：同义 topic 稳定归并；组合检索结果正确；数据变化后索引可重建

---

## M3 · 专项卷生产层（渲染 + 版本化 + 增量重建）

- **承载**：`src/organization/paper_renderer.py`、`scripts/organize_bank.py`
- **职责**
  1. 把某知识点题目渲染为"题目卷 + 解析卷"（承接 V1）。
  2. 产物**版本化 + 入库登记**（paper 目录 → 卷记录表），支持稳定寻址。
  3. **增量重建**：采集到新题后自动刷新受影响知识点，而非全量重扫。
  4. 渲染模板可扩展 Markdown / HTML / PDF。
- **输入**：知识点归组 + 渲染模板
- **输出**：`data/papers/{exam}/...` + 卷登记入库
- **契约**：`render_paper(kp,qs,with_answer)`；`rebuild_papers(exam|kp)`
- **依赖**：M2、M7、M6(指标)
- **验收**：采集新题后受影响卷自动刷新；卷可寻址可版本回溯

---

## M4 · 练习服务层（作答闭环：做题/对答案/进度/错题/计划）

- **承载**：`src/services/practice/`、`src/models/practice.py`（新）
- **职责**
  1. 作答会话：下发题(隐藏答案) → 提交答案 → 判定 → 记录。
  2. 错题本：自动收录答错题，支持重练。
  3. 学习进度与统计：正确率、覆盖知识点、连续打卡。
  4. 学习计划：按知识点/题型/难度配置目标量。
- **输入**：练习请求（exam、kp、type、difficulty、数量）
- **输出**：作答记录表、错题表、进度统计、计划表
- **契约**：练习 API（见细纲）+ 领域服务方法
- **依赖**：M2(索引出题)、M1(库)、M7
- **验收**：一次作答全链路留痕；错题可重练；统计口径一致

---

## M5 · API / 接口层（统一网关 + 鉴权 + 限流 + 错误）

- **承载**：`src/api/server.py` + `src/core/http.py`
- **职责**
  1. 统一入参校验、统一成功/错误响应体。
  2. 健康(live/ready)、指标端点。
  3. 题库查询、专项卷读取、练习闭环、采集触发端点。
  4. 可配基础鉴权(可选) + 简单限流(可选)。
- **输入**：HTTP 请求
- **输出**：统一 JSON 响应
- **契约**：见细纲 `v2_04_API契约.md`
- **依赖**：M2/M3/M4、M6、M7
- **验收**：错误码语义统一；边界输入不 500；健康分级正确

---

## M6 · 观测运维层（结构化日志 / 指标 / 健康 / 审计）

- **承载**：`src/core/log.py`、`src/core/metrics.py`、`src/core/lifecycle.py`
- **职责**
  1. 结构化字段日志，贯穿 request_id。
  2. 计数器/直方图指标；Prometheus 可抓。
  3. 健康(live/ready)；审计留痕。
- **输入**：各层事件/请求
- **输出**：日志、指标、健康状态
- **依赖**：M7
- **验收**：故障可定位；指标可看趋势；健康分级准确

---

## M7 · 基础框架层（配置中心 / 路径 / DI 容器 / 生命周期）

- **承载**：`src/core/config.py`、`src/core/paths.py`、`src/main.py`
- **职责**
  1. 配置分层加载与校验。
  2. 统一路径与目录就绪。
  3. 依赖注入容器/工厂，解耦模块级全局态。
  4. 生命周期编排（启动/优雅停机）。
- **输入**：配置文件 / 环境 / CLI
- **输出**：就绪的依赖图 + 运行上下文
- **依赖**：无（最底层）
- **验收**：非法配置拒绝启动；停机干净；多实例可并存

---

## M8 · 内容运营层（知识点目录 / 题源接入 / 模板）

- **承载**：`data/catalog/`、`data/builtin/`、文档
- **职责**
  1. 维护统一知识点目录与同义归并表（跨考试）。
  2. 扩充题源（接入第三方 API / 新增内置题 / 题质检）。
  3. 维护渲染模板与封面/版权元信息。
- **输入**：人工或脚本批量导入题
- **输出**：目录变更、题源扩充、模板
- **依赖**：M1/M2 消费它
- **验收**：新题经规范化后可出卷；目录稳定演进

---

## 模块间数据流向（端到端）

```
 题源(M8) → M1 采集入库 → M2 规范化索引 → M3 专项卷生产(卷库)
                      ↘                  ↘
                        M4 练习闭环  ← M5 API ← 用户/前端
  观测运维(M6) 贯穿全程；M7 提供地基与生命周期
```

> 每个模块都可**独立指派 1~2 名开发**并行推进；依赖见各模块"依赖"项，调度顺序见 `docs/team/team_scaling.md` 的里程碑与 RACI。
