# V2 框架蓝本 · 06 · 细纲：观测、运维与生命周期

> 让"能否用、是否健康、出问题在哪"可观测、可处置。属横向能力（M6/M7）。

---

## 1. 结构化日志

- 统一日志器 `src/core/log.py` 提供 `get_logger(name)`，输出 `key=value` 结构化字段：
  `time level module request_id event exam source count took_ms`.
- 每个 HTTP 请求 / 采集任务 / 重建任务生成一个 `request_id`，贯穿全程便于链路追查。
- 级别约定：采集失败 warn、整批失败 error、关键生命周期 info；不打印敏感信息。
- 落盘 `logs/app.log`（滚动，`logs/` 由 M7 路径确保）。

---

## 2. 健康分级

| 端点 | 语义 | 检查项 |
|------|------|--------|
| `/api/health/live` | 进程存活 | 恒返回 up |
| `/api/health/ready` | 可服务 | DB 可连、data/logs 目录可写、调度器注册状态 |

ready 检查失败时返回 503（code=5031），供负载均衡摘流。

## 3. 指标（Prometheus 文本，`/api/metrics`）

关键计数器/直方图：
- `collect_success_total{exam,source}` / `collect_failure_total`
- `questions_total{exam}`
- `fetch_duration_seconds{source}` (histogram)
- `papers_built_total{exam}` / `papers_inconsistent_total`
- `practice_attempts_total{exam,is_correct}`
- `api_requests_total{route,status}` / `api_latency_seconds`
- `last_schedule_run_timestamp`

> 无外部依赖：默认内置一个极简 Prometheus 文本输出器；需要时可插 Grafana/云监控。

## 4. 生命周期编排（src/main.py + src/core/lifecycle.py）

```
bootstrap():
  1 load+validate config          # M7 配置校验，非法即退出
  2 ensure dirs                    # data/logs
  3 connect DB + run migrations    # L2
  4 prewarm collectors / catalog
  5 register scheduler             # 定时采集+兜底重建
  6 build DI container             # db/fetch/organize/practice/paper services
run():    启动 API / 调度器
shutdown(sig):
  1 stop scheduler (wait=False)
  2 drain in-flight (grace 10s)
  3 persist/flush logs
  4 close DB
```

- `main.py` 只做编排，不混业务；`run.sh` 只转发（api|scheduler|init|test|rebuild）。
- 支持 `SIGINT`/`SIGTERM` 优雅停机（Flask 与 APScheduler 均需 hook）。

## 5. 审计与告警（渐进）

- 采集/重建/练习写日志即为审计基线。
- 待接入消息/邮件告警时，从指标与日志抽取阈值规则（采集连续失败 N 次、库 0 增长）。
