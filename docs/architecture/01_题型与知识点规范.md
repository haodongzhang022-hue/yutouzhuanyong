# 01 题型与知识点规范（类型识别）

> 让题目"能被 AI 识别类型、按类型找"，前提是**类型有统一、稳定的编码**，而非随手写的字符串。
> 本文件定义两套正交的"类型"：**题型类型(How)** 与 **知识点类型(What)**。

## 1. 正交的两个维度

| 维度 | 含义 | 取值示例 | 用于 |
|------|------|---------|------|
| 题型类型 `type` | 作答方式（How） | `mc` 单选 / `fr` 解答 | 决定渲染版式、作答方式 |
| 知识点 `kp_code` | 考什么内容（What） | `KP01` 运动学 | 决定归入哪份专项练习 |
| 难度 `difficulty` | 挑战度 | easy/medium/hard | 试卷梯度、刷题节奏 |

三者正交：同一知识点下可既有 `mc` 又有 `fr`；同一题型也可跨多个知识点。检索时三者可任意组合。

## 2. 题型类型（How）编码

| type 编码 | 含义 | 渲染要点 |
|-----------|------|---------|
| `mc` | 单选题 Multiple Choice | 题干 + A/B/C/D 选项，作答勾选 |
| `fr` | 解答题 Free Response | 题干 + 留白答题区，作答写步骤 |

> 采集源里 `multiple_choice` / `free_response` 统一映射到 `mc` / `fr`，减少歧义。

## 3. 知识点（What）—— 建议统一编码（可跨考试归并同义）

现库里的 topic 是**零散英文 + 同名不同码**，必须先归并成规范码。示例（力学部分，其余类推）：

| kp_code | 中文 | 英文/别名(aliases 归并) | 现库散见 topic |
|---------|------|------------------------|---------------|
| `KP01` | 运动学 | kinematics | kinematics, projectile_motion |
| `KP02` | 牛顿动力学 | dynamics, force_newton | dynamics, force_newton |
| `KP03` | 功能与能量 | work_energy, energy | work_energy, energy, power |
| `KP04` | 动量与冲量 | momentum, impulse_momentum | momentum, impulse_momentum |
| `KP05` | 引力 | gravitation | gravity, gravitation |
| `KP06` | 圆周运动 | circular_motion | circular_motion |
| `KP07` | 简谐运动 | SHM | simple_harmonic_motion |
| `KP08` | 转动 | rotation | rotation |
| `KP09` | 波动 | waves | waves, sound, waves_optics, optics |
| `KP10` | 电路 | circuits, electricity | circuits, electricity |
| `KP11` | 场与电磁力 | fields | electric_forces, electric_fields, magnetism, induction |
| `KP12` | 热学 | thermal | thermodynamics, thermal_energy |
| `KP13` | 流体 | fluid | fluid_mechanics |
| `KP14` | 近代物理 | modern | modern_physics, atomic_physics |

> 归并表建议存到 `data/catalog/*.knowledge.yaml`，字段含 `aliases`，脚本据此把任意 topic 归一到 `kp_code`。

## 4. 题号规范

原始 `external_id` 不可作为规范索引（前缀语义与 topic 冲突、两考试各自成体系）。
建议生成统一 `qid`，格式：

```
{EXAM}-{kp_code}-Q{序号}
示例：AP1-KP01-Q01    PB-KP01-Q01
```

- `EXAM`：`AP1`(ap_physics_1) / `PB`(physics_bowl_d1)
- `kp_code`：知识点码
- 序号：该考试该知识点内流水

`source_ref` 保留原 `external_id` 供溯源，不回写、不影响采集链路。

## 5. 类型识别落地（AI/系统如何"按类型找"）

建议组织层 `organization/topic_index.py` 提供三个索引：

1. **按知识点**：`by_kp[kp_code] -> [qid...]`
2. **按题型**：`by_type[type] -> [qid...]`
3. **按难度**：`by_difficulty[level] -> [qid...]`

任意组合查询（如"运动学 + 选择题 + 中难度"）直接取交集即可，全部落到规范化 qid 上。
