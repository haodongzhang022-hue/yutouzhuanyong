## 1. 配置分层与覆盖

加载顺序（后者覆盖前者）：
```
默认值(src/core/config.py)
  < config/settings.yaml
  < 环境变量(前缀 YTZ_)
  < CLI 参数
```

示例（YAML + 环境覆盖）：
```yaml
app:
  name: AP Physics 专项练习系统
  version: 2.0.0
  debug: false
  port: 8080            # 可被 YTZ_APP__PORT 覆盖
database:
  path: data/physics_bank.db
scheduler:
  enabled: true
  daily_fetch_time: "08:00"
  daily_fetch_count: 5
collectors:
  ap_physics_1:
    enabled: true
    per_source_limit: 5
    sources:
      - { name: 内置题库, type: builtin, path: data/builtin/ap_physics_1.json }
practice:
  enabled: true
metrics:
  enabled: true
```
- 校验：未知考试枚举、空 source、非法调度时间 → 启动即报错并给出可读 message。
- 敏感项（API key/token）只允许 `YTZ_*` 环境变量注入，不入 YAML。

## 2. 运行模式（run.sh）

| 模式 | 命令 | 说明 |
|------|------|------|
| api | `python -m src.main --mode api` | 起 API + 调度 |
| scheduler | `python -m src.main --mode scheduler` | 仅调度（定时采集+重建） |
| init | `python scripts/fetch_once.py` | 首启全量导入 |
| rebuild | `python scripts/organize_bank.py` | 手动重建专项卷 |
| test | `python -m pytest` | 全量测试 |
| validate | `python scripts/validate_papers.py` | 卷一致性校验 |

## 3. 部署形态

### 本地 / 单机（当前）
- Dockerfile 构建镜像，`run.sh api` 启动，SQLite + 本地 `data/` 卷挂载持久化。

### 演进（预留，不阻塞）
- 后端无状态化 + 外部 SQLite/Postgres 可切 → 便于横向多实例。
- 专项卷产物进对象存储/静态托管，API 读登记表。
- 采集调度独立 worker，API 独立实例。

### 配置模板
- `config/settings.yaml`（本地默认）+ `config/settings.prod.yaml.example`（生产样例，含环境变量占位）。
