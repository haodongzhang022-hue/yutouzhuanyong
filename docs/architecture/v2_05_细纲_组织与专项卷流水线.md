# V2 框架蓝本 · 05 · 细纲：组织层与专项卷生产流水线

> 承接 V1 已落地的组织层成果，定义 V2 下"采集→组织→产卷"的**增量/事件化**流水线。

---

## 1. 目标

1. 采集入库的新题**即时**反映到对应知识点的专项卷，无需每次全量重扫。
2. 专项卷产物**版本化可寻址**，供 API 与前端稳定读取，且可回溯旧版本。
3. 主数据 / 索引 / 卷三者通过重建任务保持一致性，允许"只读派生 + 可重建"。

---

## 2. 流水线各阶段

```
阶段A  采集入库(M1)                新题写入 questions
阶段B  规范化回填(M2)              对受影响 exam/kp 刷新 kp_code/norm_qid 派生列
阶段C  增量重建(M3)                仅重渲染受影响的 {exam,kp_code} 专项卷
阶段D  登记与发布(M3)              写 paper_runs + 更新卷版本/目录
```

### 触发方式（三者互补）
1. **事件触发（推荐）**：M1 入库成功后广播 `question.created(exam, source)`，调度器消费后仅对该 exam 跑 C。
2. **定时兜底**：每日采集后统一触发一次增量重建，防止事件丢失。
3. **手动重建**：`POST /api/rebuild/papers` 全量或按 kp 重建（对应 `scripts/organize_bank.py`）。

---

## 3. 增量重建规则

- 以 `kp_code` 为重建最小粒度：某 kp 新增题 → 只重渲染该 kp 的题目卷/解析卷。
- 通过 `questions.kp_code` 索引查该 kp 全部题，按统一排序（难度→qid）渲染。
- 重建结果写 `paper_runs`（trigger=incremental），并把该 kp 卷 version +1。
- 旧版本文件保留于 `data/papers/_archive/{exam}/{kp}/{version}/`，目录/索引指向最新。

---

## 4. 产物布局（承接 V1，扩展版本目录）

```
data/papers/
  {exam}/
    INDEX.md                       # 最新目录（人读）
    ai_index.json                  # 最新结构化索引
    {kp}_KPxx_Name.md              # 最新题目卷
    {kp}_KPxx_Name.answer.md       # 最新解析卷
  _archive/                        # 历史版本（可回溯）
    {exam}/{kp_code}/{version}/...
```

---

## 5. 渲染模板扩展（渐进）

- `Markdown`（V1，基线）→ 提交到 git 便于 diff。
- `HTML`（v2 可选）：公式 LaTeX→MathJax 排版，适合打印/网页预览。
- `PDF`（v2 可选）：依赖 pandoc/weasyprint，做成独立 renderer，不影响 md 基线。
- 模板抽成 `src/organization/templates/{paper_md,paper_html,paper_cover}`，可配。

---

## 6. 一致性与校验

- `scripts/validate_papers.py`（v2 交付）：核对每 kp 的卷文件与 `questions` 题数、qid 集合是否一致。
- 不一致报警（日志 + 指标 `papers.inconsistent`），交由重建修复。
- 专项卷构建成功/失败均入指标，供 M6 观测。
